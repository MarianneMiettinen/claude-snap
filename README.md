# claude-snap
Take a picture on your phone and Claude Snap brings it directly to Claude Code.

Screenshot on phone → tap Send → the image is in your Claude Code project's `incoming/` folder, and a ready-to-paste prompt with the exact path is on your PC's clipboard.

No app store, no account, no cloud. The phone talks to a small bridge on your PC over your own Wi-Fi.

## Run it

Needs Node.js 18+.

```
npm install
npm start
```

Or double-click **Start Claude Snap.cmd**. The PC page opens at http://localhost:5195.

The first time you start it, Windows may ask whether Node.js can use the network. Allow **Private networks** only. If your home Wi-Fi is set to "Public" in Windows, the phone can't reach the bridge until you switch that network to Private.

## Pair your phone (once)

1. On the PC page, click **Pair a phone**.
2. Scan the QR code with your phone's camera and open the link.
3. Optional: add the page to your home screen (Share → Add to Home Screen) so it opens like an app.

The phone and PC must be on the same Wi-Fi. If the PC's IP address changes, pair again.

## Send an image

Open the page on your phone → **Take photo** or **Choose from gallery** → check the destination → **SEND IMAGE**.

The file is saved as `<project>\incoming\phone-YYYY-MM-DD-HHMM.png`. Names never collide and existing files are never overwritten. The confirmation only appears after the PC has written the file and checked its size. Then paste into Claude Code (Ctrl+V). The prompt is already on the clipboard.

## How the "latest project" is found

Claude Code keeps local files that the bridge reads, and never writes:

- `~/.claude/sessions/<pid>.json`: one per running session (session id, start folder). The bridge checks that the process is still alive.
- `~/.claude/projects/<folder>/<session>.jsonl`: the transcripts. Their last-modified time is "last activity".

If a session was started inside a project (the folder has `.git`, `package.json` or `pyproject.toml`), that folder is the project. If it was started in a workspace folder that holds many projects, like `Claude Code-projektit\`, the bridge looks at the session's most recent file paths and working directories. The subfolder it was last working in is the project. If there's no clear subfolder, the project is marked uncertain, and the phone asks you to choose instead of guessing.

These files are Claude Code internals, not a public API. If a future version changes them, detection finds fewer projects and you can still pick or add projects manually on the PC page. There's also always a **No project (Downloads inbox)** destination.

Manually added projects (PC page → Add a project) can use their own image subfolder, for example `screenshots`.

## Direct Claude Code integration (Milestone 5) — findings

I checked what's actually possible with Claude Code 2.1.x:

| Mechanism | Can it put an image into a *running* session? |
|---|---|
| CLI (`claude -p`, `--resume`) | No. It starts a new process or a new turn, not the session you're typing in. |
| Hooks (`UserPromptSubmit`) | Partly. It's supported, and it could add "new image at …" as context automatically the next time you send a message. |
| MCP server | Partly. Claude could call a "latest phone image" tool, but only when it decides to. |
| Session messaging pipe in `~/.claude/sessions` | Internal and undocumented. Not used. |

So there's no supported way to push into a live session. The clipboard prompt is the reliable path. The most promising next step is a `UserPromptSubmit` hook, which would remove even the paste.

## Security

- Pairing uses a one-time code from the QR (valid 10 minutes). The phone then gets its own random device token. The PC stores only a hash of it in `bridge-config.json`.
- Requests without a valid device token are rejected. Unpair a phone from the PC page.
- Only private/LAN addresses can connect. The PC control page (pairing, settings) only answers on `localhost`.
- Uploads are checked by their actual bytes (PNG, JPEG, WEBP, HEIC) and limited to 25 MB. Filenames are generated by the bridge, never taken from the phone. Nothing received is ever executed.
- Images are not stored anywhere except the destination folder.
- **Not encrypted in transit:** traffic on your Wi-Fi is plain HTTP. Anyone on the same network with a packet sniffer could see images being sent. On home Wi-Fi that's usually fine. Don't use it on public Wi-Fi. HTTPS would need a self-signed certificate that phones warn about on every visit, which is why it's not in v1.

## Known limits

- HEIC photos are saved, but Claude Code can't read HEIC. Screenshots (PNG/JPEG) are fine, and iPhones usually convert to JPEG when uploading from the browser anyway.
- Only works while the bridge is running. There's no tray icon yet: it's a console window plus the page at localhost:5195.
